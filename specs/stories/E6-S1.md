# E6-S1: Chat API and intent classification with safety precedence

- **ID:** E6-S1
- **Epic:** E6 - Customer Conversation, Promise-to-Pay and Simulated Payment
- **Layer:** API
- **Slice:** 1
- **Group:** F
- **depends_on:** E5-S2, E5-S3, E3-S5

## Description

Provide the customer chat API that discloses the AI, classifies each message into the seven intents with a schema-valid result plus advisory safety signals (vulnerability and special requests), and applies safety precedence so sensitive signals override transactional ones (D-016). It reports UNKNOWN and REQUEST_HUMAN handling to escalation and derives identifiers only from the bound customer context. Rate limiting protects against runaway loops.

## Acceptance Criteria

1. The first assistant message in a conversation states it is an AI assistant and every response includes a 'talk to a human' option flag
2. Intent output validates against the schema with label in the seven allowed values, confidence in [0,1] and rationale, and an unknown label, including VULNERABLE_CUSTOMER, is rejected
3. The structured interpretation also carries advisory safety signals: vulnerability_detected (boolean), an optional vulnerability_category enum, a vulnerability_rationale string, and a special_request enum of NONE, SETTLEMENT or POLICY_EXCEPTION, and an output missing vulnerability_detected fails schema validation
4. When a message contains both a transactional and a sensitive intent, or vulnerability_detected is true, the sensitive signal wins, automated treatment for the topic pauses, and no PTP or payment proposal is executed
5. Consecutive UNKNOWN classifications produce a clarification question on the first and on the second, and the third is reported for escalation as UNRESOLVED_UNKNOWN, while REQUEST_HUMAN is reported for immediate escalation on the first message
6. More than the configured requests per minute to the chat endpoint returns 429
7. Customer and account identifiers used in tool arguments always come from the server-side bound context, and a message asking for another customer's information returns no such data and is audited
