# E6-S3: Simulated PAY_NOW and PaymentEvent

- **ID:** E6-S3
- **Epic:** E6 - Customer Conversation, Promise-to-Pay and Simulated Payment
- **Layer:** Service
- **Slice:** 1
- **Group:** G
- **depends_on:** E6-S1, E2-S2, E2-S5

## Description

Implement the simulated PAY_NOW flow: present service-returned payable amounts, require confirmation, record a synthetic PaymentEvent and update synthetic balances. All outputs are labelled simulated and no real payment occurs (D-021).

## Acceptance Criteria

1. The assistant presents only payable amounts returned by the payable-amounts service, and a payment is recorded only through an explicit customer confirmation API action referencing a currently valid payable-amount proposal
2. On confirmation exactly one PaymentEvent is recorded with amount, outcome, source, Clock timestamp and simulated=true, and the balance is reduced by that Decimal amount
3. A duplicate or replayed payment confirmation with the same idempotency key does not create a second event or double-count recovery
4. The chat confirmation text contains the word 'simulated' and the code contains no import of a payment gateway SDK or HTTP call to an external payment host
5. On confirmation the domain service revalidates authorization, policy, snapshot freshness and proposal validity, and a stale or altered payment proposal is rejected with PROPOSAL_INVALID and records no PaymentEvent
