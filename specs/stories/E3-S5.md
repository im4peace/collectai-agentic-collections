# E3-S5: Customer binding and object-level authorization

- **ID:** E3-S5
- **Epic:** E3 - Access Control and Delinquent Portfolio
- **Layer:** API
- **Slice:** 1
- **Group:** E
- **depends_on:** E3-S1

## Description

Bind the CUSTOMER demo persona server-side to one synthetic customer_id and enforce object-level authorization on every customer-facing request so a customer can never access another customer's accounts, conversations, PTPs, payments, arrangements, hardship records, disputes or escalation cases (BRD failure row 14).

## Acceptance Criteria

1. The CUSTOMER persona is bound server-side to exactly one synthetic customer_id, and a client-supplied customer_id in a request is ignored or rejected
2. For every customer-facing request the server validates the persona, the bound customer_id and ownership of the requested resource, covering accounts, conversations, PTPs, PaymentEvents, arrangements, hardship records, disputes and escalation cases
3. A cross-customer request returns the same not-found response as a nonexistent resource, with no resource information leaked in the body or headers
4. An authorization test matrix runs every customer-owned resource type against own, other-customer and nonexistent ids and passes for all cells
5. A denied cross-customer access writes an audit event with persona, bound customer_id and endpoint but not the target resource's contents
