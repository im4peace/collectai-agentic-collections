# E2-S5: Data freshness and record consistency checks

- **ID:** E2-S5
- **Epic:** E2 - Deterministic Rules Engine
- **Layer:** Service
- **Slice:** 1
- **Group:** B
- **depends_on:** E1-S1, E1-S2

## Description

Implement deterministic snapshot freshness detection and internal-consistency validation so consequential transitions are re-checked and the rules engine refuses inconsistent financial or account records (BRD failure rows 5 and 24).

## Acceptance Criteria

1. The freshness check compares a snapshot's as_of and version to the current record and the freshness threshold and returns FRESH, STALE or UNKNOWN
2. A stale snapshot or a version mismatch causes the consequential action to be refused with reason STALE_DATA and the refreshed context to be returned
3. When freshness cannot be established (UNKNOWN) the action fails closed with no state change and is reported for escalation with reason AMBIGUOUS_VALIDATION
4. The rules engine refuses internally inconsistent records (DPD not matching bucket, negative balance, overdue amount above outstanding balance) with reason INCONSISTENT_RECORD and flags the record
5. Every rules service invoked with an inconsistent or unfresh record returns a failure result and never an eligibility, option or score
