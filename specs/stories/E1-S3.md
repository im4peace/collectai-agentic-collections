# E1-S3: PostgreSQL persistence and synthetic seed data

- **ID:** E1-S3
- **Epic:** E1 - Foundation, Policy and Persistence
- **Layer:** Repository
- **Slice:** 1
- **Group:** B
- **depends_on:** E1-S1, E1-S2

## Description

Create the PostgreSQL schema through versioned migrations with NUMERIC money columns, customer ownership on every customer-owned record, snapshot as_of and version on delinquency records, repositories for core entities, and a seed script that loads 200-1,000 synthetic delinquent accounts across CARD and PERSONAL_LOAN. The seed validates data and scans for prohibited patterns.

## Acceptance Criteria

1. Seed script loads between 200 and 1,000 synthetic accounts including both CARD and PERSONAL_LOAN types and is idempotent when run twice
2. Money columns are PostgreSQL NUMERIC and a round-trip of Decimal('0.10') through the repository returns Decimal('0.10') exactly
3. Seed validation rejects inconsistent records (DPD not matching bucket, negative balance) and flags them with a reason instead of loading silently
4. Prohibited-pattern scan over seed data finds zero real-looking PII: emails only on example.com, phones only in the fictional range, no 13-19 digit card numbers, CVV, PIN or government ID patterns
5. The schema is created by versioned migrations that apply cleanly to an empty database and can be re-run without error
6. Every customer-owned record (account, conversation, PTP, PaymentEvent, arrangement, hardship case, dispute, escalation case) carries an owning customer_id foreign key, and a repository query by customer_id returns only that customer's records
7. DelinquencyRecord stores an as_of timestamp and a monotonically increasing version, and every update increments the version
