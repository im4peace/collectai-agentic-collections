# E8-S3: Dispute identification and suppression

- **ID:** E8-S3
- **Epic:** E8 - Arrangements, Hardship and Disputes
- **Layer:** Service
- **Slice:** 3
- **Group:** H
- **depends_on:** E7-S1

## Description

Implement the customer-facing half of Journey C (US-011): detect DISPUTE intent, capture structured category and reason idempotently, never judge validity, pause automation for the disputed item and route to dispute review with context preserved.

## Acceptance Criteria

1. A dispute message produces a schema-valid Dispute with category (for example AMOUNT_INCORRECT) and customer reason text, and status OPEN
2. No AI output states or implies the dispute is valid or invalid (guardrail check on 20 scripted replies passes)
3. After a dispute is opened no PTP or arrangement can be created on the disputed item and the attempt returns DISPUTED_ITEM until a human action
4. The dispute escalation with reason DISPUTE is routed to DISPUTE_REVIEW and preserves the full conversation and supporting context
5. Dispute creation is idempotent: the same idempotency key, or a repeated dispute message for the same item while a dispute is open, returns the existing dispute and creates no duplicate
