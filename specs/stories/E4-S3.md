# E4-S3: Next-Best-Action recommendation

- **ID:** E4-S3
- **Epic:** E4 - Customer 360 and Next-Best-Action
- **Layer:** Service
- **Slice:** 1
- **Group:** F
- **depends_on:** E4-S1, E5-S2, E5-S3

## Description

Generate a schema-valid next-best-action with rationale for an account using the AI orchestration layer, grounded in deterministic data. The AI explains priority using returned factors, cannot change records or invent eligibility, and every recommendation is logged.

## Acceptance Criteria

1. The recommendation output validates against a schema with action (one of the allowed actions), rationale text and referenced factor ids, and a schema-invalid MOCK output triggers one retry then a safe 'human review' recommendation
2. The rationale is rejected and replaced by templated text if it cites a factor, amount or option not returned by the deterministic services
3. For an account with active dispute, hardship or open escalation the only action returned is ESCALATE_TO_HUMAN_REVIEW regardless of AI output
4. Each recommendation creates an audit event with model id, prompt version, rule-set version and output, and no financial record changes during generation
5. If audit persistence fails the recommendation endpoint returns an AUDIT_UNAVAILABLE state with no recommendation body, so the recommendation is never presented as governed
