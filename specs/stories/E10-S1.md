# E10-S1: Evaluation dataset and MOCK/LIVE runner

- **ID:** E10-S1
- **Epic:** E10 - Evaluation, Analytics and Portfolio Deliverables
- **Layer:** Service
- **Slice:** 1
- **Group:** H
- **depends_on:** E7-S1

## Description

Build the Python evaluation framework with a versioned labelled dataset of at least 50 synthetic conversations in Slice 1 (no maximum, expected to grow beyond 200), covering intents, sensitive and safety scenarios, a runner supporting MOCK and LIVE modes, and provenance metadata. LIVE runs are manually triggered.

## Acceptance Criteria

1. The dataset file records version, provenance (authorship method, synthetic statement) and at least 50 labelled cases covering all seven intents, edge, adversarial, policy and vulnerable-signal cases
2. Running the runner in MOCK produces an EvalRun with mode MOCK, per-case pass or fail and no network calls
3. Running in LIVE mode requires an explicit flag and API key, and refuses to run in CI
4. Each EvalRun stores model id, prompt version, dataset version, rule-set version, date, token usage and estimated cost where available
5. The dataset includes FINANCIAL_HARDSHIP, DISPUTE, REQUEST_HUMAN, vulnerable-customer safety, exceptional-arrangement request, policy-exception request, settlement request and ambiguous-validation cases, and every case carries its expected intent, safety signals and expected escalation reason where applicable
6. The dataset is versioned, has no maximum size enforced, and adding cases produces a new dataset version that the runner and reports record
7. An architecture test fails if any production package imports the evaluation package
