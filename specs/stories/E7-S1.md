# E7-S1: Escalation case creation and safe handling of sensitive intents

- **ID:** E7-S1
- **Epic:** E7 - Escalation and Human Review
- **Layer:** Service
- **Slice:** 1
- **Group:** G
- **depends_on:** E6-S1, E2-S6, E5-S4

## Description

Create EscalationCase records transactionally with their audit events when the AI proposes escalation, when the customer asks for a human, or when a sensitive intent, safety signal or special request is detected. Destination and priority come only from the routing service. Pauses automated recommendations, returns respectful safe messages, provides the minimal Slice 1 escalation list API, and never depends on the later full review queue (BRD 7.1, scenarios 12, 13, 21).

## Acceptance Criteria

1. An OPEN EscalationCase linking the conversation is created with the matching EscalationReason for each trigger: REQUEST_HUMAN immediately on the first request, UNRESOLVED_UNKNOWN only after two clarification turns, AI_FAILURE_FALLBACK on provider failure or tool-cap breach, FINANCIAL_HARDSHIP, DISPUTE, VULNERABLE_CUSTOMER when vulnerability_detected is true, SETTLEMENT_REQUEST when special_request is SETTLEMENT, POLICY_EXCEPTION when special_request is POLICY_EXCEPTION, and AMBIGUOUS_VALIDATION for PAYMENT_PLAN before the arrangement workflow ships or when validation cannot authorize an action
2. The queue, reviewer role and priority of each case come from the routing service using the active PolicyRuleSet, the audit event records reason, queue, reviewer role and rule-set version, and no LLM output or proposal can supply a queue or role
3. The customer response acknowledges respectfully, states a human colleague will follow up, and contains no plan, relief, settlement, approval or opinion on dispute validity
4. The escalation and its audit event are written in one transaction; if the escalation write fails the customer is told the handoff was not completed and automated collection actions for the account stay paused
5. Creating an escalation sets automated_treatment_suppressed for the account (or item) per the PolicyRuleSet suppression parameters, and stays set until a human decision
6. Escalation creation is idempotent: the same idempotency key, or a second trigger for the same conversation and reason while a case is OPEN, returns the existing case and creates no duplicate
7. GET /api/escalations, allowed for COLLECTIONS_OFFICER, returns a minimal list with reason, priority, age, status, a customer and account reference, and a link to the Customer 360 and case context
