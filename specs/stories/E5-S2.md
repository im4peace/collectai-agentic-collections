# E5-S2: Structured output validation and fail-closed write path

- **ID:** E5-S2
- **Epic:** E5 - AI Orchestration Foundation
- **Layer:** Service
- **Slice:** 1
- **Group:** D
- **depends_on:** E5-S1, E1-S4

## Description

Implement the fail-closed write path: LLM output to Pydantic schema validation, authorization and policy validation, then a deterministic domain service and audit. Includes one bounded retry, safe response and escalation on failure (BRD 10.3, 13.1 rows 1, 9, 18).

## Acceptance Criteria

1. Malformed LLM output is retried exactly once, and if the retry is also invalid the result is a safe response with no state change and the invalid output stored in the audit event
2. A provider timeout is retried once, then returns a safe fallback with a human-handoff offer and no state change
3. Model output that conflicts with a deterministic rule result is rejected, the rule result prevails and a policy-conflict audit event is written
4. The hostile-provider test: 50 random or adversarial MOCK outputs cause zero state changes without passing schema, authorization and domain-service validation
5. If audit persistence fails for a non-state-changing AI response that is a material recommendation, the orchestrator returns a safe unavailable state, does not present the recommendation as governed, and records an operational failure where possible
6. Each AI interaction records provider latency, tool-call duration, end-to-end interaction duration, token usage where available, model id, prompt version, PolicyRuleSet version and correlation id in its audit event
