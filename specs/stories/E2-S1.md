# E2-S1: Deterministic Collections Priority service

- **ID:** E2-S1
- **Epic:** E2 - Deterministic Rules Engine
- **Layer:** Service
- **Slice:** 1
- **Group:** B
- **depends_on:** E1-S1, E1-S2

## Description

Implement the rules-engine service that computes a priority score, band and contributing factors per delinquent account from DPD, overdue amount, broken PTP count, active dispute, hardship status and recent contact outcome using PolicyRuleSet weights. It also flags accounts needing human treatment.

## Acceptance Criteria

1. Given fixed inputs and policy-v1 the service returns the same score, band and ordered factor list on 100 repeated calls
2. Each returned factor names the input attribute, its value and its weighted contribution, and the contributions sum to the score
3. Band thresholds from the rule set map scores at each boundary (just below and at cut-off) to the expected band
4. Accounts with an active dispute, active hardship case or open escalation return human_treatment=true and automated_treatment_suppressed=true
5. The rules engine package imports nothing from AI orchestration or LLM provider modules (checked by an architecture test)
6. Priority parameters are read from the active PolicyRuleSet, and a missing or invalid parameter returns POLICY_UNAVAILABLE with no score produced
