# E8-S1: Payment arrangement conversation flow

- **ID:** E8-S1
- **Epic:** E8 - Arrangements, Hardship and Disputes
- **Layer:** Service
- **Slice:** 2
- **Group:** H
- **depends_on:** E2-S3, E7-S1, E2-S5

## Description

Implement Journey B1: on PAYMENT_PLAN intent collect required information, obtain eligible options from the rules service, present only those, take the customer's selection and an explicit confirmation action, revalidate, then create the arrangement via the domain service. Exceptional requests are handed to escalation and handled by E7-S4.

## Acceptance Criteria

1. The assistant presents only options returned by the eligibility service and the amounts in the message match the service Decimal values
2. When no option is eligible the customer is told options cannot be provided now, is offered a human, and no alternative is fabricated
3. The arrangement is created only after the customer selects an option and confirms through an explicit confirmation API action referencing a currently valid eligible option, and the domain service revalidates authorization, policy, freshness and option validity before creating it with status ACTIVE
4. A rules engine failure results in no options, a customer message that options cannot be provided now, an AMBIGUOUS_VALIDATION escalation and an audit event with the rule-set version
5. Audit records the eligibility result, chosen option, confirmation and PolicyRuleSet version
6. Arrangement creation is idempotent: the same idempotency key returns the original arrangement and creates no second one
7. A requested arrangement classified EXCEPTIONAL is never offered or created by this flow and is handed to escalation with reason EXCEPTIONAL_ARRANGEMENT
8. A conflicting active PTP or arrangement blocks the new arrangement with CONFLICTING_ACTIVE_ITEM and the customer is offered amend, cancel or an officer
9. get_eligible_options returns arrangement options from the eligibility service in this slice without changing its tool contract
