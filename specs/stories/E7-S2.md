# E7-S2: Review queue API with reviewer actions

- **ID:** E7-S2
- **Epic:** E7 - Escalation and Human Review
- **Layer:** API
- **Slice:** 2
- **Group:** H
- **depends_on:** E7-S1

## Description

Expose the review queue and reviewer actions APPROVE, REJECT, MODIFY, REQUEST_MORE_INFORMATION and ESCALATE with mandatory reasons, policy-permitted constraints, optimistic version checks, a case state machine, idempotent decisions and full audit (BRD 5.7). Reviewer ESCALATE supplies a whitelisted reason and the routing service picks the destination.

## Acceptance Criteria

1. REJECT, MODIFY and ESCALATE without a reason return 422, and REQUEST_MORE_INFORMATION without a note returns 422
2. APPROVE returns 409 with reason NOT_PERMITTED_BY_POLICY when the active PolicyRuleSet does not permit approval of that case type
3. MODIFY accepts only an option from the deterministic eligible set and rejects a free-form amount
4. A decision submitted with a stale case version returns 409 and leaves the case unchanged, so two officers cannot both decide
5. Every reviewer action and status transition writes an audit event, and only COLLECTIONS_OFFICER may act on cases in the COLLECTIONS_REVIEW, COLLECTIONS_EXCEPTION_REVIEW, HARDSHIP_REVIEW, DISPUTE_REVIEW and VULNERABLE_CUSTOMER_REVIEW queues while COLLECTIONS_MANAGER and COMPLIANCE_RISK receive 403
6. The reviewer ESCALATE action accepts only a reason from the whitelisted routing.reviewer_escalation_reasons, the routing service determines the destination, and a free-form destination is rejected with 422
7. Submitting the same reviewer decision with the same idempotency key returns the original result and does not repeat the transition, and a different decision on an already decided case returns 409
8. The case follows the state machine OPEN, IN_REVIEW, AWAITING_INFORMATION, DECIDED or RE_ROUTED, and any transition outside it is rejected with 409
