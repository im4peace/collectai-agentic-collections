# E1-S1: Domain types, Decimal money and injectable Clock

- **ID:** E1-S1
- **Epic:** E1 - Foundation, Policy and Persistence
- **Layer:** Types
- **Slice:** 1
- **Group:** A
- **depends_on:** []

## Description

Define the shared domain types (Account with type CARD or PERSONAL_LOAN, DelinquencyRecord, PromiseToPay, PaymentEvent, EscalationCase, AuditEvent and enums including EscalationReason, review queue and reviewer role) plus a money type and a Clock abstraction. Every later story builds on these. Supports D-009 and D-014.

## Acceptance Criteria

1. Money is represented with Python Decimal; float input is rejected and API serialization emits strings such as "1250.50"
2. Money rejects negative values and more than 2 decimal places with distinct reason codes NEGATIVE_AMOUNT and OVER_PRECISION
3. Clock interface has a system implementation and a settable test/simulated implementation whose now() returns exactly the value set and advances by advance(days=n)
4. Account.type accepts only CARD or PERSONAL_LOAN, and enums PTP status (PENDING, KEPT, BROKEN, CANCELLED) and intent labels (PAY_NOW, PROMISE_TO_PAY, PAYMENT_PLAN, FINANCIAL_HARDSHIP, DISPUTE, REQUEST_HUMAN, UNKNOWN) reject any other value
5. EscalationReason accepts exactly REQUEST_HUMAN, UNRESOLVED_UNKNOWN, AI_FAILURE_FALLBACK, EXCEPTIONAL_ARRANGEMENT, FINANCIAL_HARDSHIP, DISPUTE, SETTLEMENT_REQUEST, AMBIGUOUS_VALIDATION, VULNERABLE_CUSTOMER, POLICY_EXCEPTION and HIGH_RISK_COMPLIANCE, the review queue and reviewer role enums reject any other value, and VULNERABLE_CUSTOMER is not an accepted intent label
