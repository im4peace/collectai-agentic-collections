# E2-S3: Payment arrangement eligibility service

- **ID:** E2-S3
- **Epic:** E2 - Deterministic Rules Engine
- **Layer:** Service
- **Slice:** 2
- **Group:** B
- **depends_on:** E1-S1, E1-S2

## Description

Implement deterministic eligibility that returns the list of eligible arrangement options (installment count, installment amount, start date) for an account, or none, using PolicyRuleSet limits, and classifies a requested arrangement as eligible or exceptional (D-024).

## Acceptance Criteria

1. For a fixed account and policy-v1 the service returns a stable list of options whose installments sum exactly to the arranged amount (no rounding loss)
2. An account that fails eligibility (for example already has an active arrangement or DPD beyond the limit) returns an empty option list with a reason code
3. A requested term or date outside permitted ranges is classified EXCEPTIONAL and one inside is classified ELIGIBLE
4. A conflicting active PTP or arrangement blocks a new arrangement with reason CONFLICTING_ACTIVE_ITEM and lists amend or cancel as the permitted path
5. If the rules engine raises an internal error the service returns a failure result (no options, no guess) and records the rule-set version
