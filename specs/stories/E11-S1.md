# E11-S1: Journey A end-to-end: Promise-to-Pay

- **ID:** E11-S1
- **Epic:** E11 - End-to-End Journey Verification
- **Layer:** Service
- **Slice:** 1
- **Group:** J
- **depends_on:** E3-S3, E4-S2, E6-S5, E9-S2, E9-S3

## Description

Automated end-to-end verification of Journey A: Portfolio, Customer 360, AI chat, PTP with confirmation, simulated payment or clock, KEPT or BROKEN, and the audit trail, using Playwright for the UI plus API and domain assertions.

## Acceptance Criteria

1. A Playwright test as COLLECTIONS_OFFICER opens the Portfolio, selects an account and reaches Customer 360 showing the priority band with contributing factors and the AI next-best-action panel
2. A Playwright test as the bound CUSTOMER completes the PTP conversation: PROMISE_TO_PAY is identified, service-returned values are shown, an explicit Confirm click is required, and the PTP appears as PENDING
3. Using the demo clock and simulated PAY_NOW, one scenario pays a PTP in two partial simulated payments and it becomes KEPT, and another advances the clock past the due date and it becomes BROKEN, with API assertions that each PaymentEvent has simulated=true
4. As COMPLIANCE_RISK the audit viewer shows the full decision chain for the journey with model id, prompt version and PolicyRuleSet version, and API assertions confirm an audit event for every state transition
5. The journey test runs in MOCK mode in CI with no network access to the provider
