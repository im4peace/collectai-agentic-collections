# E1-S2: Versioned PolicyRuleSet and validated application configuration

- **ID:** E1-S2
- **Epic:** E1 - Foundation, Policy and Persistence
- **Layer:** Config
- **Slice:** 1
- **Group:** A
- **depends_on:** []

## Description

Provide the versioned PolicyRuleSet defined in specs/policy-ruleset-contract.md (priority, PTP, arrangement, exception authority, contact frequency, freshness, suppression, vulnerability, escalation routing and compliance review parameters) plus validated application configuration. Seeded numeric values are chosen at design time and must satisfy the contract. Missing or invalid required configuration fails closed.

## Acceptance Criteria

1. Loading the seeded rule set returns a version string (for example 'policy-v1') and every required parameter defined in specs/policy-ruleset-contract.md is present with the type, unit and range the contract specifies
2. Rule set validation rejects a config with a missing required parameter, a wrong-typed or out-of-range value, negative weights or unordered band cut-offs, and the application fails to start with a named error identifying the parameter
3. With no valid active rule set at runtime every rules service returns POLICY_UNAVAILABLE and grants no eligibility, options or priority (fail closed)
4. Rule sets are immutable per version: changing any parameter creates a new version, exactly one version is active, and an earlier version referenced by an audit event can still be loaded read-only with its original values
5. The routing table maps every EscalationReason to exactly one queue and reviewer role as defined in the contract, and a table missing a reason or naming an unknown queue or role fails validation
6. Configuration reads the model name from ANTHROPIC_MODEL and LIVE or MOCK mode from an environment variable, and no model id or secret is hard-coded in source
7. Validated application configuration keys (tool call cap per turn, retry bound, maximum clarification turns, chat rate limit) are checked at startup against the contract ranges, the tool call cap defaults to 5, and a value of 0 or 21 fails startup with a named error
8. A .env file is git-ignored and .env.example lists required variables with placeholder values only
